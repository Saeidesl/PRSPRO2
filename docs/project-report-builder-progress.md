# گزارش پیشرفت — گزارش‌ساز پویا و قابل شخصی‌سازی پروژه

آخرین به‌روزرسانی: 2026-10-25

## هدف
تبدیل صفحه «گزارش از پروژه‌ها» در PMS به گزارش‌ساز قابل تنظیم، سازگار با APIهای موجود و رابط فارسی/راست‌به‌چپ، با خروجی قابل چاپ و CSV.

## مراحل و وضعیت

| مرحله | وضعیت | شواهد / توضیح |
|---|---|---|
| 1. بررسی ساختار فعلی گزارش و قرارداد بک‌اند | انجام شد | صفحه `pages/reports.html`، ماژول `js/modules/reports.js`، مسیرهای `/reports/projects` و `/reports/project/:id` و `ReportService.js` بررسی شدند. بک‌اند فعلی گزارش پروژه و داده‌های ملزومات را برمی‌گرداند. |
| 2. فیلتر و مرتب‌سازی رویدادهای گزارش | پیاده‌سازی شد؛ آزمون خودکار در حال اجرا | جست‌وجو در عنوان/نوع رویداد، واحد، ثبت‌کننده و توضیحات؛ فیلتر تاریخ شروع/پایان؛ مرتب‌سازی جدیدترین/قدیمی‌ترین. |
| 3. انتخاب بخش‌های گزارش | پیاده‌سازی شد؛ آزمون خودکار در حال اجرا | انتخاب/حذف بخش اطلاعات پروژه، رویدادها، نیاز ملزومات، محاسبات ملزومات و سفارش/تحویل. |
| 4. قالب‌های شخصی | پیاده‌سازی شد؛ آزمون خودکار در حال اجرا | ذخیره، اعمال و حذف قالب‌ها در فضای ذخیره‌سازی مرورگر فعلی. این نسخه قالب‌ها را بین دستگاه‌ها همگام نمی‌کند. |
| 5. خروجی CSV | پیاده‌سازی شد؛ آزمون خودکار در حال اجرا | خروجی UTF-8 با BOM برای پشتیبانی بهتر از فارسی؛ اطلاعات پروژه، رویدادهای انتخاب‌شده، ملزومات، محاسبات و سفارش‌ها. |
| 6. رابط واکنش‌گرا و چاپ A4 | پیاده‌سازی شد؛ انتشار Pages در حال بررسی | کنترل‌های گزارش‌ساز در صفحه موجود اضافه شده‌اند و CSS برای موبایل/دسکتاپ و چاپ حفظ شده است. |
| 7. اعتبارسنجی فرانت‌اند و بک‌اند | در حال اجرا | GitHub Actions برای بررسی نحو جاوااسکریپت، تست‌های فرانت‌اند، تست‌های بک‌اند و QA بین دو مخزن اجرا می‌شود. |
| 8. آزمون دستی در مرورگر و با حساب واقعی | انجام‌نشده | از این محیط امکان تأیید تعامل واقعی مرورگر، دسترسی کاربر، داده واقعی و خروجی PDF چاپگر وجود ندارد؛ تا زمان دسترسی به شواهد معتبر، موفق اعلام نمی‌شود. |

## تغییرات فرانت‌اند روی main
- `pages/reports.html`: کنترل‌های فیلتر، انتخاب بخش‌ها، مدیریت قالب‌ها و خروجی CSV؛ استایل واکنش‌گرا.
- `js/modules/reports.js`: منطق فیلتر/مرتب‌سازی، ذخیره و اعمال قالب، انتخاب بخش‌های گزارش و خروجی CSV.

## تصمیم درباره بک‌اند
در این مرحله API موجود برای گزارش پروژه کافی به نظر می‌رسد؛ تغییری در بک‌اند یا ساختار Google Sheets انجام نشده تا از تغییرات غیرضروری و ریسک داده‌های تولید جلوگیری شود. این تصمیم باید با تست قرارداد بین دو مخزن تأیید شود.

## معیارهای پذیرش نهایی
- [ ] تمام بررسی‌های خودکار مرتبط سبز باشند.
- [ ] گزارش یک پروژه مجاز بارگذاری شود و پروژه خارج از محدوده دسترسی افشا نشود.
- [ ] فیلترهای جست‌وجو و تاریخ و مرتب‌سازی نتایج درست بدهند.
- [ ] تغییر بخش‌ها هم در صفحه و هم در چاپ اعمال شود.
- [ ] ذخیره/اعمال/حذف قالب بدون خطا انجام شود.
- [ ] CSV شامل داده‌های انتخاب‌شده و فارسی خوانا باشد.
- [ ] چاپ A4 و چیدمان موبایل/دسکتاپ در مرورگر واقعی بررسی شود.
- [ ] نتیجه انتشار GitHub Pages بررسی شود؛ انتشار Apps Script فقط در صورت نیاز به تغییر بک‌اند لازم است.

## یادداشت ایمنی
تست‌ها نباید داده‌های واقعی تولید را تغییر دهند. سبز بودن بررسی ایستا به‌تنهایی جایگزین آزمون پذیرش در مرورگر و با حساب کاربری واقعی نیست.
