# گزارش پیشرفت — گزارش‌ساز پویا و قابل شخصی‌سازی پروژه

آخرین به‌روزرسانی: 2026-10-25

## هدف
تبدیل صفحه «گزارش از پروژه‌ها» در PMS به گزارش‌ساز قابل تنظیم، سازگار با APIهای موجود و رابط فارسی/راست‌به‌چپ، با خروجی قابل چاپ و CSV.

## مراحل و وضعیت

| مرحله | وضعیت | شواهد / توضیح |
|---|---|---|
| 1. بررسی ساختار فعلی گزارش و قرارداد بک‌اند | انجام شد | صفحه `pages/reports.html`، ماژول `js/modules/reports.js`، مسیرهای `/reports/projects` و `/reports/project/:id` و `ReportService.js` بررسی شدند. بک‌اند فعلی گزارش پروژه و داده‌های ملزومات را برمی‌گرداند. |
| 2. فیلتر و مرتب‌سازی رویدادهای گزارش | پیاده‌سازی شد؛ تست واحد سبز | جست‌وجو در عنوان/نوع رویداد، واحد، ثبت‌کننده و توضیحات؛ فیلتر تاریخ شروع/پایان؛ مرتب‌سازی جدیدترین/قدیمی‌ترین. |
| 3. انتخاب بخش‌های گزارش | پیاده‌سازی شد؛ تست‌های خودکار سبز | انتخاب/حذف بخش اطلاعات پروژه، رویدادها، نیاز ملزومات، محاسبات ملزومات و سفارش/تحویل. |
| 4. قالب‌های شخصی | پیاده‌سازی شد؛ تست واحد سبز | ذخیره، اعمال و حذف قالب‌ها در فضای ذخیره‌سازی مرورگر فعلی. این نسخه قالب‌ها را بین دستگاه‌ها همگام نمی‌کند. |
| 5. خروجی CSV | پیاده‌سازی شد؛ تست واحد سبز | خروجی UTF-8 با BOM برای پشتیبانی بهتر از فارسی؛ اطلاعات پروژه، رویدادهای انتخاب‌شده، ملزومات، محاسبات و سفارش‌ها. |
| 6. رابط واکنش‌گرا و چاپ A4 | پیاده‌سازی شد؛ GitHub Pages در commit فعلی با موفقیت منتشر شد | کنترل‌های گزارش‌ساز در صفحه موجود اضافه شده‌اند و CSS برای موبایل/دسکتاپ و چاپ حفظ شده است. |
| 7. اعتبارسنجی فرانت‌اند و بک‌اند | سبز در commit کد 56dfc1b2 | Frontend checks و PMS cross-repository QA و PMS frontend agent suite با موفقیت پایان یافتند؛ تست‌های جدید گزارش‌ساز نیز در مجموعه تست فرانت‌اند اجرا شدند. |
| 8. آزمون سرتاسری احراز هویت‌شده | مسدود به علت نبود تنظیم staging | گزارش خودکار موجود وضعیت `blocked-no-staging-api` را ثبت کرده است. برای آزمون ورود و مسیر گزارش باید `PMS_STAGING_API_BASE_URL` به یک استقرار آزمایشی جداگانه متصل باشد؛ API تولید برای تست ورود استفاده نمی‌شود. آزمون دستی PDF و دسترسی نقش‌ها نیز هنوز تأیید نشده است. |

## تغییرات فرانت‌اند روی main
- `pages/reports.html`: کنترل‌های فیلتر، انتخاب بخش‌ها، مدیریت قالب‌ها و خروجی CSV؛ استایل واکنش‌گرا.
- `js/modules/reports.js`: منطق فیلتر/مرتب‌سازی، ذخیره و اعمال قالب، انتخاب بخش‌های گزارش و خروجی CSV.

## تصمیم درباره بک‌اند
در این مرحله API موجود برای گزارش پروژه کافی به نظر می‌رسد؛ تغییری در بک‌اند یا ساختار Google Sheets انجام نشده تا از تغییرات غیرضروری و ریسک داده‌های تولید جلوگیری شود. این تصمیم باید با تست قرارداد بین دو مخزن تأیید شود.
